# ADR 0128 — Original content cited by name in mods

Status: accepted (2026-10-05, card t_401e6b69, points 13, 12 and 19). Complements ADR 0083, whose
rule "a number only designates an original entry without a name" is abandoned.

## Context
After ADR 0083, a mod author still had to write numbers for the original content:
`base` / `original` of an enemy, original turret weapons (`tur`, `turrets[].weapon`),
launched enemies (`elaunchtype`, `eenemydie`), special damage codes (99, 100+n, 250+n), and
`eventtype` / `eventdat` of levels. The original data names neither the enemies nor the enemy
weapons, and episodes 4-5 reload a different enemy table (699 slots out of
1,701 differ from those of episodes 1-3).

## Decision
- Names computed from the data (`tyrian-mods/src/originals.rs`), stable as long as the data
  does not change, published in `rewrite/mods/original-names.json` (versioned file, regenerated by
  `tyrian-mods catalog`, checked in CI by `published_original_names_match_the_data`) with a
  preview sheet per bank in `docs/original-enemies/` (drawn by `tyrian-render`):
  - enemy: `<bank theme>_<rank of the first image>` (+ `b`, `c`… if same image and different
    statistics), `no_image_<NN>` without an image; the same name designates the same record in the
    two tables (slot specific to each table);
  - enemy weapon (slots 1..255, those an enemy can carry): `<sprite of the first
    projectile>_<NN>`.
- Damage: `0..98`, `"freeze"`, `{ "pierce": 0..5 }`, `{ "chain": "<original weapon>" }`; any other
  number is an error.
- A single version of the format: numbers are rejected everywhere (message saying what to write),
  the shipped mods and the template are converted once.
- Mod levels (point 12): named events `{ "time": 300, "spawn": "my_drone", "x": 130 }`.
  A single table (`tyrian-mods/src/levels.rs:EVENT_KINDS`, 87 types: all those of the engine) serves
  the reader and the exporter; the editor's "Tyrian" dock exports through
  `TyrianMods.export_level` (`tool` class). Named special values (`"random"`, `"keep"`,
  `{ "picked": n }`…), numeric codes rejected; `eventtype`/`eventdat` rejected (unknown keys).
  Engine duplicates exported under a single name: 83 → `stop_map`, 68 → `replace_enemies`, text 16
  with an enemy number (corrupted original records, replayed as 10) → `spawn_ground2`,
  type 108 (unknown, ignored) → `nothing`; fields not read by the engine are not exported.
- Mod enemy sprites (point 19): `sprites/enemies/<original enemy name>.png` replaces the
  first image (`egraphic[0]`) of that enemy in its bank; a subfolder (old convention
  `<bank>/<image>.png`) or unknown name = error. No shipped mod contained any.
- The bank themes reuse the folder names of `data/reference/sprites/levels/`
  (formerly generated by `utils/gen_levels_mapping.py`); banks without a folder keep `bank_NN`.

## Evidence
- Full resolution of the four shipped mods (table fix, sprites, shop, identities,
  start, enemies, enemy weapons, levels, diagnostics), episodes 1 to 5, byte-for-byte identical
  before/after conversion; 2000-tick games with identical fingerprint (ep1_09, ep2_01..ep5_01).
- Test `original_content_and_damage_codes_are_cited_by_name` (names accepted, numbers rejected).
- Levels: the 70 original levels (59,677 events) exported in the named format and read back
  play 3000 ticks with identical fingerprint (`named_level_events_round_trip_every_original_level`);
  the shipped level of `example_behaviors`, converted, gives a byte-for-byte identical resolution;
  gdUnit4 suite `level_export_test.gd` (dock export read back without error by the loader).
- `--strict` golden masters unchanged (no active mod).

## Consequences
A mod that cited an original enemy by number must cite it by name (`MODDING.md` §7.5).
Changing the original data changes the names: rerun `tyrian-mods catalog`.
